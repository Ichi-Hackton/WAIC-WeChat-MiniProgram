## 核心组件
- **规则规划器**：rulePlan(intent, ctx)，基于关键字和模式匹配生成任务计划，支持高铁购票、星巴克点单、商品购物、服务预约、附近POI搜索等多个业务领域。
- **LLM 客户端**：plan(intent, ctx, availableSkills)，负责调用云端 LLM，并在开发环境失败时降级到规则规划器。
- **解析器**：toPlan(llmOutput, intent, planId)，将规则或 LLM 的输出标准化为 Plan，包含严格的模式验证和动作特定绑定字段白名单校验。
- **规划器提示**：buildPlannerPrompt(ctx)，提供上下文信息和附近POI搜索的优化提示。
- **类型定义**：Plan、Task、AgentContext 等，确保上下游数据结构一致。
- **编排器与调度器**：Orchestrator 管理状态机，Scheduler 执行 DAG 任务。
- **验证器与绑定解析器**：validator.ts 和 binding.ts 提供通用的 JSON Schema 验证功能和 inputBindings 路径解析。

**更新** 新增了动作特定的绑定字段白名单验证机制，增强了附近POI搜索功能，改进了错误处理和用户体验。

## 详细组件分析

### rulePlan 函数实现逻辑
rulePlan 是规则式规划的主入口，接收用户意图与 Agent 上下文，返回与 LLM Planner 同构的 PlannerLLMOutput。其核心逻辑包括：
- **意图分类**：通过正则表达式判断是否涉及高铁/火车查询购票、星巴克门店查询与点单、商品购物、服务预约、附近POI搜索等。
- **参数抽取**：从意图中提取日期、城市、座位类型、饮品名、商品信息、服务信息、附近地点关键词等关键参数。
- **任务构建**：根据意图类别生成对应的 Task 列表，包含 skillId、action、input、dependsOn、summary 等字段。
- **写操作标记**：若意图包含购买相关关键词，则追加下单类任务，交由后续 checkpoint 进行人类确认。
- **附近POI搜索**：新增的附近地点搜索功能，支持便利店、药店、银行等任意品类的位置搜索。

**更新** 新增了附近POI搜索功能，增强了意图识别的准确性和覆盖范围，改进了错误处理和用户体验。

### 规则匹配机制
规则匹配基于正则表达式对自然语言意图进行模式匹配，主要匹配项包括：
- **城市关键词集合**：支持简繁体并列，按出现顺序取前两个城市作为出发站与到达站。
- **座位类型映射**：商务座、一等座、二等座、硬座等映射到枚举值。
- **日期抽取**：后天、明天、今天默认，支持具体日期格式。
- **饮品识别**：美式、摩卡、拿铁等。
- **商品识别**：耳机、手表、保温杯、咖啡豆、按摩仪、跑步鞋等。
- **服务识别**：羽毛球、洁牙、体检、游泳、理发等。
- **附近地点关键词提取**：支持"附近的便利店"、"哪里有打印店"等模式的智能提取。
- **购买意图**：买、订、下单、来一杯、帮我点等关键词触发写操作任务。
- **预约时段**：支持具体时间点和时间段词汇映射。

**更新** 新增了附近地点关键词的智能提取功能，支持更丰富的地理位置搜索场景。

### 规则优先级与冲突解决策略
- **优先级**：规则按意图类别分支处理，先判断是否涉及火车/高铁，再判断是否涉及咖啡/星巴克、购物、预约、附近搜索；各业务域可并行存在，互不干扰。
- **冲突解决**：同一意图可能同时命中多个规则（例如既提到"高铁"又提到"咖啡"），此时会分别生成对应任务链，不存在互斥冲突。
- **购买意图**：无论属于哪一类业务，只要包含购买关键词，都会追加下单类任务，且必须经过 checkpoint 确认。
- **结算优化**：对于购物场景，如果检测到结算意图，直接跳过搜索步骤，减少不必要的 API 调用。
- **附近搜索排他性**：附近搜索已排除所有专属域词（咖啡、购物、预约、票务、交通、天气），仅承接无专属 SKILL 的品類詞。

**更新** 新增了附近搜索的排他性逻辑，避免了与其他业务域的冲突。

### 与 LLM 规划器的协作关系
- **正常路径**：client.plan 调用云端 LLM，解析输出后生成 Plan。
- **降级路径**：当云端 LLM 不可用（开发环境）时，client.plan 捕获异常并调用 rulePlan，再通过 toPlan 转换为标准 Plan，traceId 保留用于追踪。
- **降级判定**：devFallbackReason 检测 LLMError 或 CloudNetworkError，仅在开发环境触发降级，避免掩盖真实 LLM 故障。
- **错误处理增强**：改进了错误检测和日志记录，提供更详细的故障信息。

**更新** 增强了错误处理机制，提供了更好的故障诊断信息。

### 增强的解析器验证机制
新增的动作特定绑定字段白名单验证机制确保规划输出的数据完整性和一致性：
- **JSON 结构验证**：确保 LLM 输出符合预期的 JSON 结构。
- **必填字段检查**：验证每个任务的 skillId、action、input、dependsOn 等必填字段。
- **占位符检测**：防止 LLM 输出未填充的占位符值，如 `<需要用户提供>` 或 `TBD`。
- **数据类型验证**：确保字段类型符合预期，如字符串、数字、数组等。
- **动作特定绑定字段白名单**：针对每个 action 定义了允许绑定的 fromField 路径，防止 LLM 幻觉导致的非法路径引用。
- **路径绑定验证**：验证 inputBindings 中的 fromTaskId 和 fromField 引用有效性，支持通配符匹配（如 priceCentByTrain.*）。

**更新** 新增了完整的动作特定绑定字段白名单验证系统，显著提升了规划的准确性和可靠性，有效防止 LLM 幻觉导致的绑定错误。

### 附近POI搜索功能

- **关键词提取**：智能提取"附近的便利店"、"哪里有打印店"等自然语言描述中的地点品类。

- **搜索执行**：调用地图技能进行POI搜索，返回按距离排序的结果列表。
- **用户体验优化**：提供友好的提示信息，引导用户补充缺失的地点品类。

## 故障排查
- **常见问题**：
  - 规则未匹配：检查意图中的关键词是否与预定义正则匹配。
  - 参数缺失：确认 extractDate、extractCities、extractSeatType、extractDrink、extractProduct、extractService、extractNearbyKeyword 是否能正确抽取。
  - 降级未触发：检查 devFallbackReason 的判断条件与环境标志。
  - 验证失败：检查模式验证错误信息，确认数据结构是否符合要求。
  - 绑定字段错误：检查 BINDING_FIELDS_BY_ACTION 白名单配置，确认 fromField 路径是否合法。
  - 附近搜索失败：检查定位权限状态，确认关键词提取是否正确。
- **日志定位**：
  - client.plan 中的 warn 与 error 日志用于定位 LLM 调用失败与降级原因。
  - Orchestrator 的状态转移日志用于确认流程是否正常推进。
  - 验证器的错误信息用于定位数据完整性问题。
  - 绑定解析器的错误信息用于定位 inputBindings 路径解析问题。
