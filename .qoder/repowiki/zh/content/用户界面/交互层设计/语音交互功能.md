## 引言
本文件面向 WAIC-WeChat-MiniProgram 的语音交互能力，聚焦以下目标：
- 说明语音输入处理流程：录音权限获取、音频数据捕获、实时语音识别。
- 说明 STT（Speech-to-Text）服务集成方案：API 调用、结果解析与错误处理。
- 说明语音指令预处理与后处理：意图识别与命令格式化。
- 说明语音反馈实现：TTS（Text-to-Speech）播放控制与触发时机。
- 提供配置选项与性能优化策略：音频格式选择、网络请求优化与用户体验改进。

当前仓库已实现完整的云端 STT 服务，基于 MiniMax asr-1.0 模型，支持 base64 编码音频传输，提供稳定的语音识别能力。

## 架构总览
语音交互的整体流程如下：
- 用户在页面点击麦克风按钮，进入语音入口。
- 调用录音模块启动录音，获取临时录音文件路径。
- 将录音文件读取为 base64 编码并通过 JSON 负载发送至云端 STT 接口。
- 云端 STT 服务解码 base64 音频并调用 MiniMax asr-1.0 API 进行识别。
- 识别结果返回给小程序端，进入编排器进行意图理解与任务规划。
- 根据任务执行结果更新 UI 状态与消息卡片。

## 详细组件分析

### 语音输入处理流程
- 录音权限与设备能力检测
  - 优先使用新版 RecorderManager；若不可用则提示录音 API 不可用。
  - 通过 `isVoiceAvailable()` 函数检测录音能力可用性。
- 音频数据捕获
  - 设置最大录音时长（默认 60s）与音频格式（mp3，16kHz 单声道）。
  - 监听停止与错误回调，返回临时文件路径或抛出错误。
- Base64 音频转换
  - 使用 `readFileBase64()` 函数将临时录音文件读取为 base64 编码字符串。
  - 通过文件系统 API 完成二进制到 base64 的转换。

### STT 服务集成方案
- API 调用
  - 小程序端通过 `postContainer` 调用云端容器，路径为 `/api/stt/recognize`。
  - 传入 base64 编码的音频数据和环境 ID。
- 云端处理
  - STT 服务接收 base64 音频并进行解码和验证。
  - 将音频转换为 multipart/form-data 格式调用 MiniMax asr-1.0 API。
  - 支持语言提示（language: 'zh'）提升中文识别准确率。
- 结果解析
  - 标准响应包含 code、message、data。
  - 成功时从 data.text 提取识别文本，data.durationSec 提供音频时长信息。
- 错误处理
  - 当 code 不为 0 或 data 为空时抛出错误，携带 message 或 code 信息。
  - 区分可重试错误（503）和不可重试错误（业务失败码）。

### 云端 STT 服务实现
- 配置管理
  - 支持独立配置（STT_BASE_URL、STT_API_KEY）或回退到 LLM 配置。
  - 自动拼接 MiniMax speech_to_text 端点 URL。
- 音频处理
  - 验证 base64 音频的有效性、长度和内容。
  - 设置 700KB 音频大小上限，防止过大请求。
  - 使用 FormData 构造 multipart/form-data 请求。
- 超时控制
  - 上游 API 调用超时设置为 30 秒。
  - 区分超时错误和其他网络连接错误。
- 错误分类
  - 400/422 错误：音频格式非法或敏感内容，返回业务失败码。
  - 其他错误：认证失败、余额不足、限流等，返回 503 可重试错误。

## 性能与优化
- 音频格式选择
  - 使用 mp3 格式，16kHz 采样率，单声道，兼顾兼容性与体积。
  - 60s 录音文件大小约 500KB，base64 后约 670KB，远低于 1MB 限制。
- 网络请求优化
  - 使用云端封装的统一超时与重试机制，提升稳定性。
  - 30 秒超时设置，适合短音频识别场景。
- 传输优化
  - Base64 编码在 JSON 负载中传输，避免 multipart 复杂性。
  - 服务端进行 base64 解码和音频验证，确保数据安全。
- 用户体验改进
  - 录音期间显示明确的状态提示（"正在听"）。
  - 识别过程中显示加载状态（transcribing）。
  - 对 STT 失败提供友好的错误提示和重试入口。

## 故障排查指南
- 录音 API 不可用
  - 现象：调用 startVoiceRecognition 直接报错，提示"录音能力未就绪"。
  - 排查：确认基础库版本与设备能力，检查 RecorderManager 可用性。
- STT 调用失败
  - 现象：云端返回 code 不为 0 或 data 为空。
  - 排查：检查云端容器路径、环境与网络连通性；查看错误 message。
- Base64 音频问题
  - 现象：STT 服务返回"audioBase64 不是合法的 base64 内容"。
  - 排查：确认音频文件读取成功，base64 编码正确。
- 音频过大
  - 现象：STT 服务返回"音頻過大"错误。
  - 排查：检查录音时长和格式，确保不超过 700KB 限制。
- 云端调用超时或网络异常
  - 现象：callContainer 抛出错误，触发重试。
  - 排查：检查网络状况与服务器状态；必要时调整超时与重试策略。
- MiniMax API 错误
  - 现象：返回 400（音频格式非法）、422（敏感内容）、401（认证失败）等。
  - 排查：检查音频格式、内容合规性和 API 密钥配置。

## 结论
当前仓库已实现完整的语音交互系统，具备以下核心能力：
- **录音封装**：支持 RecorderManager 录音，提供会话式 API。
- **云端 STT 服务**：基于 MiniMax asr-1.0 模型，提供稳定的语音识别。
- **Base64 传输**：支持在 JSON 负载中传输 base64 编码音频。
- **错误处理**：完善的错误分类和重试机制。
- **性能优化**：合理的音频格式选择和传输优化。

系统采用前后端分离架构，小程序端负责录音和用户交互，云端服务负责语音识别和错误处理。通过 base64 编码和 JSON 传输，简化了数据传输复杂度，同时保证了良好的性能和用户体验。未来可在此基础上扩展更多语音功能和优化策略。
