模块按依赖方向分层组织（interaction → core → skills → llm，单向不可逆），顶层 `src/app.ts` 仅导出 `createAgentRuntime` 单例工厂，由小程序入口 `miniprogram/app.ts` 在 `onLaunch` 中注入 `globalData.agent`。

- `core/`：`Orchestrator` 实现规范 §5.1 的状态机（idle→understanding→planning→confirming_plan→executing→aggregating→completed/failed），通过 `ALLOWED_TRANSITIONS` 表约束转移；`scheduler.ts` 负责任务调度与回滚；`context.ts` 构造跨层共享的 `AgentContext`。
- `skills/`：`registry.ts` 维护全局 `SkillRegistry` 单例，提供注册/查询/slim 列表；`adapter.ts` 统一调用已注册 Skill；内置 skill 位于 `skills/builtin/`（train-12306、coffee-starbucks、payment-aicard）。
- `llm/`：`client.ts` 封装云端 LLM 调用，`parser.ts` 解析 JSON Schema，`rule-planner.ts` 与 `prompts/planner.ts` 提供规则式规划能力。
- `services/`：对云开发能力的薄封装（cloud/storage/llm/payment/identity），被上层以依赖注入方式消费。
- `storage/`：会话与会话历史持久化（session + cache）。
- `types/`：集中声明所有跨层类型（agent-state、plan、task、skill、checkpoint、context 等）。
- `utils/`：日志、重试、ID 生成、校验等横切工具。
- `interaction/`：UI 侧交互（卡片渲染、Checkpoint 确认、语音 STT），通过回调注入 Orchestrator，避免 core 反向依赖 interaction。
- 小程序页面 `pages/index/` 仅订阅 Runtime 事件进行渲染，app.json 配置导航栏、权限与 sitemap。
