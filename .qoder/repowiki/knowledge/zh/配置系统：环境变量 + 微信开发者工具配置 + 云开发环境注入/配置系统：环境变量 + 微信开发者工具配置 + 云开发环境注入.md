## 1. 使用的系统与方式

本仓库采用**三层配置来源**，无统一配置框架，全部通过原生机制加载：

- **Node.js 后端（cloudrun）**：纯 `process.env` 读取，零依赖。
- **微信小程序前端（miniprogram）**：微信运行时全局 API（`wx.cloud.init`、`getAccountInfoSync`）与项目配置文件（`project.config.json`、`app.json`）。
- **微信开发者工具工程配置**：根目录 `project.config.json`。

未使用 `.env` 文件、YAML/TOML 配置、feature flag 库或集中式 config loader。

## 2. 关键文件

- `project.config.json` — 微信开发者工具工程级配置（appid、miniprogramRoot、编译器插件等）。
- `miniprogram/app.json` — 小程序应用级配置（pages、window、permission、requiredPrivateInfos）。
- `cloudrun/src/server.ts` — 后端入口，监听 `PORT` 环境变量。
- `cloudrun/src/llm-chat.ts` — LLM 代理端点，读取 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`。
- `miniprogram/src/services/cloud.ts` — 微信云开发容器调用封装，负责 `wx.cloud.init` 初始化与环境判定。
- `miniprogram/app.ts` — 小程序 App 入口，引用品牌常量并懒加载 Agent Runtime。

## 3. 架构与约定

### 3.1 后端环境变量（cloudrun）

后端仅通过 `process.env` 直接读取，默认值在代码中提供：

| 变量 | 用途 | 默认值 |
|---|---|---|
| `PORT` | 监听端口（微信雲托管要求） | `80` |
| `LLM_BASE_URL` | LLM 服务基础地址 | 必填（无默认） |
| `LLM_API_KEY` | LLM 鉴权密钥 | 必填（无默认） |
| `LLM_MODEL` | 模型名称 | `'deepseek-chat'` |

所有变量在 `cloudrun/src/server.ts`（第 125 行）和 `cloudrun/src/llm-chat.ts`（第 56–74 行）中直接访问，无集中声明或校验层。

### 3.2 小程序应用配置（miniprogram）

- `project.config.json`：由微信开发者工具解析，定义 `miniprogramRoot: "miniprogram/"`、`compileType: "miniprogram"`、`libVersion: "3.0.0"`、`appid` 及 TypeScript 编译插件等。
- `miniprogram/app.json`：小程序运行时配置，声明 pages、window 样式、权限（`scope.userLocation`）、隐私接口（`getLocation`）。
- 品牌相关字符串（`BRAND_NAME`、`BRAND_TAGLINE`、`BRAND_VERSION`）集中在 `miniprogram/src/types/brand.ts`，由 `miniprogram/app.ts` 注入 `globalData`，禁止硬编码（见该文件注释规范）。

### 3.3 云开发环境注入（wx.cloud）

`miniprogram/src/services/cloud.ts` 提供统一的云开发接入层：

- `ensureCloudInit(env: string)`：幂等初始化 `wx.cloud.init({ env })`，模块级缓存已初始化的 env，避免重复 init。
- `isDevEnv()`：基于 `wx.getAccountInfoSync().miniProgram.envVersion` 判定是否为 develop/trial/release，结果缓存于模块变量。
- `callContainer(opts)`：封装 `wx.cloud.callContainer`，统一超时（默认 15s）、重试（最多 3 次，baseDelay 600ms）、错误归一化（`CloudNetworkError`），并在开发环境将云端不可用降级为 `code: -1`，保证本地演示可用。

## 4. 约定与约束

- **后端配置只来自 `process.env`**：`server.ts` 与 `llm-chat.ts` 直接读取环境变量，无配置文件加载逻辑。
- **`PORT` 必须存在**：`server.ts` 第 125 行 `Number(process.env.PORT ?? 80)` 表明微信雲托管要求通过环境变量传入端口。
- **LLM 凭据不硬编码**：`LLM_BASE_URL`、`LLM_API_KEY` 在 `llm-chat.ts` 中直接从 `process.env` 读取，无默认值，部署时必须注入。
- **小程序云开发环境 ID 作为参数传递**：`ensureCloudInit` 的 `env` 参数由调用方传入，而非从配置文件读取；调用方需确保传入正确的云环境 ID。
- **开发/生产行为差异通过 `isDevEnv()` 控制**：`cloud.ts` 中 `isDevEnv()` 缓存判定结果，用于决定是否允许云端不可用时降级为 mock 响应。
- **`project.config.json` 是微信开发者工具的权威工程配置**：`miniprogram/app.ts` 注释明确说明其 `miniprogramRoot` 指向 `miniprogram/` 目录。
- **品牌字符串集中管理**：`miniprogram/app.ts` 注释声明「所有可见品牌字串皆引用 BRAND_NAME，禁止硬编码」，强制品牌文案从 `src/types/brand.ts` 导入。
- **小程序运行时配置位于 `app.json`**：页面路由、窗口样式、权限声明均在此文件中，未被代码动态覆盖。
